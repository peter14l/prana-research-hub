# PRANA Research Hub: Data Integrity & Provenance Audit Report
**Milestone 2 Forensic Audit**
**Date**: November 2026
**Target Air Shed**: Kolkata–Howrah Conurbation, West Bengal, India

---

## 1. Executive Summary

This forensic audit investigates the origins, integrity, and provenance of all data, monitoring stations, external integrations, and research claims in the PRANA Research Hub codebase.

Prior to Milestone 2, the application presented a functional research workstation layout; however, several underlying data streams and metrics relied on synthetic baselines or unverified assumptions:
1. **Pollutant Observations Origin**: All 10,647 observation records in the database were synthetically generated by `seed_data.py`. While physically realistic (reflecting CPCB breakpoints and diurnal winter inversion curves), their provenance was incorrectly labeled as live `"WBPCB CAAQM Telemetry Pipeline"` without explicit demonstration tags.
2. **Completeness Figure Discrepancy**: The previously reported `"99.8% completeness"` was calculated as $\frac{\text{valid observations}}{\text{total existing observations}}$ ($10,565 / 10,647 = 99.23\%$). It did **not** represent true temporal completeness (expected observation hours vs. received observation hours).
3. **External Provider Integration Reality**:
   * **OpenAQ v3 API**: Requires an explicit API key via header `X-API-Key`. Unauthenticated requests return `HTTP 401 Unauthorized`. The platform must truthfully declare this integration as `AUTH_REQUIRED` rather than `ACTIVE`.
   * **WBPCB AQMS Portal** (`https://aqmsdata.wbpcb.gov.in/`): Functions as a web UI with session forms, but does not offer a public, unauthenticated REST API endpoint. Automated live polling is unsupported; reliable ingestion requires manual CSV export.
   * **CPCB CCR Portal** (`https://app.cpcbccr.com/ccr_docs`): Regulatory documentation and PDF downloads, no streaming telemetry API.
   * **Open-Meteo**: High-resolution meteorological reanalysis/forecast endpoint is functional without authentication.
4. **Monitoring Stations Reality**: All 9 stations are genuine statutory CAAQM stations operated by WBPCB/CPCB with accurate coordinates and physical locations. However, they lacked formal verification metadata, statutory station IDs (e.g., CPCB Site IDs `site_5002` to `site_5010`), and audit timestamps.
5. **Research Claims Traceability**: Studies by TERI (2025) and CSIR-NEERI (2020) were summarized accurately, but lacked exact table, figure, and page citations.

## 3. Discrepancy Analysis: Completeness Calculation

### Previous Implementation
```python
# In backend/routers/data_quality.py (Milestone 1)
total_validated = db.query(ValidatedObservation).count() # 10,647
valid_count = db.query(ValidatedObservation).filter_by(is_valid=True).count() # 10,565
completeness_rate_pct = round((valid_count / total_validated * 100.0), 2) # 99.23%
```
* **Flaw**: This calculation simply measured the fraction of existing records that were not flagged as outliers. If a station failed to report for 5 days out of 7, this formula still returned ~99% if the few received records were within normal ranges!

### Milestone 2 Standard
Temporal completeness must be calculated against an explicit expected time window:
$$\text{Temporal Completeness (\%)} = \frac{\text{Received Valid Hourly Observations}}{\text{Expected Hours} \times \text{Expected Pollutants}} \times 100\%$$
* Every completeness metric displayed in the platform must provide its exact **numerator** and **denominator** (e.g., `164 / 168 hours = 97.6%`).

## 4. Remediation Action Plan

1. **Database Schema Update**: Add `data_classification` (`VERIFIED`, `IMPORTED`, `DERIVED`, `DEMO`, `UNVERIFIED`), `original_source_record`, and provenance hashes to observation records.
2. **Station Verification System**: Augment `monitoring_stations` with CPCB statutory site codes, verification status, verification date, and official registry links.
3. **Data Quality Engine**: Build an automated verification engine detecting missing hours, duplicates, invalid units, non-monotonic timestamps, stuck sensors, and calculate true numerator/denominator completeness.
4. **Source Reliability Module**: Accurately reflect provider connectivity, authentication barriers, and error messages (truthful reporting: no fake "LIVE" status for disconnected APIs).
5. **Citation Traceability**: Link all source profiles and research findings to specific page numbers and table/figure references in statutory reports.
6. **Dashboard Transparency**: Add a prominent global Data Integrity indicator displaying exact percentages of `VERIFIED`, `IMPORTED`, `DERIVED`, and `DEMO` data.
